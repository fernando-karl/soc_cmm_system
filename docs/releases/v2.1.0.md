# 2.1.0 — every question under its own aspect

**If you run 2.0.x, upgrade and rebuild.** In 2.0.0 and 2.0.1, 270 of the 622
questions were filed under the wrong aspect, so the scores for the aspects below
were computed over the wrong questions.

## What was wrong

`scripts/extract_soc_cmm.py` generates the questionnaire from the official
SOC-CMM® workbook. It assigned each question to the last section header it had
passed in the `_Output` sheet, and two quirks of that sheet broke it:

- some headers are written with a space (`S 2 - Security incident Management`),
  which the header pattern did not match, so those questions fell into the
  previous section;
- a block near the end of the sheet re-lists capability items from other
  aspects under `M5`, so they were filed under Detection Engineering.

| Aspect | 2.0.x | 2.1.0 |
| --- | --- | --- |
| Security Incident Management | **0** | 50 |
| Forensic analysis | **0** | 38 |
| Detection Engineering & Validation | 193 | 18 |
| Security Monitoring | 119 | 41 |
| Log / Network / Endpoint Monitoring | 16 / 16 / 16 | 60 / 56 / 71 |
| SecOps Automation | 32 | 46 |
| Threat Intelligence | 41 | 55 |

Questions are now assigned by their own id — `S 2.3.1` is Services aspect 2 —
which is how the workbook itself defines them. The fix also recovers **27
questions** that were silently dropped: the questionnaire is now **649 questions
and 3245 answer options**, all scorable. The 2.3.3 (basic) dataset had the same
bug (283 of 664 questions) and is regenerated too.

## Portuguese

The 132 strings new to this release are translated and marked
`origin: machine` in `dataset/translations/pt_br.json`, pending review like the
rest. A fresh install serves all 649 questions in Portuguese.

## So it cannot happen again

`tests/test_dataset_integrity.py` checks that every question's id matches its
aspect, that no aspect is empty, that question ids are unique, that translation
files have no gaps, and that the committed dataset equals a fresh extraction
from the workbook. Against the 2.0.1 data, five of these fail.

## Also in this release

`LICENSE` is now the verbatim CC BY-SA 4.0 legal code, so GitHub detects the
licence. Attribution remains in `NOTICE`; the licence itself is unchanged.

## Upgrading

Question ids change, and `scripts/init_db.py` never overwrites an existing
questionnaire, so an existing database keeps the mis-filed one. Export anything
you need, then rebuild as described in [v2.0.0.md](v2.0.0.md). Scores from
assessments taken on 2.0.x are not comparable with 2.1.0 for the aspects above.
